# Rival Auto Parts — закрытый B2B-портал автозапчастей

Оптовый портал для дилеров автозапчастей: умный поиск по каталогу,
персональные остатки по складам, оформление заявок с переходом к менеджеру в
WhatsApp и админ-панель. Каталог и остатки синхронизируются из **1С** по
HTTP-сервису.

---

## 🔗 Онлайн-демо (ничего ставить не нужно)

**https://rival-auto-parts.vercel.app** — доступы `admin/admin123`,
`manager/manager123`, `client/client123`.

> **плавного показа** запустите локально — за 3 шага ниже (работает мгновенно).

## 🚀 Быстрый старт локально (Windows)

**Поставить один раз:** [Node.js 20+](https://nodejs.org) ·
[PostgreSQL 15+](https://www.postgresql.org/download/windows/) (при установке задайте
пароль пользователя `postgres` = `postgres`, порт `5432`) ·
[Git](https://git-scm.com).

```powershell
git clone https://github.com/nmoldakhmetov/rival-auto-parts.git   # либо распакуйте присланный ZIP
cd rival-auto-parts
# ВАЖНО: положите в эту папку файл db-seed.sql (его пришлёт владелец проекта)
powershell -ExecutionPolicy Bypass -File .\setup.ps1   # поставит всё + загрузит каталог (~2 мин)
npm run dev                                            # http://localhost:3000
```

> 📦 **Про `db-seed.sql`:** это готовая база на **5283 товара** с ценами. В
> репозитории её нет (коммерческие данные не выкладываются в облако) — владелец
> присылает файл отдельно. Просто положите его в папку проекта **до** запуска
> `setup.ps1`. Если файла нет — скрипт создаст пустой каталог с демо-аккаунтами, а
> товары можно подтянуть из 1С (войдите `admin` → «Обзор» → синхронизация).

Скрипт `setup.ps1` сам поставит зависимости, создаст базу и загрузит данные. Если
пароль PostgreSQL у вас не `postgres` — поправьте `$DbPassword` в `setup.ps1` и
`DATABASE_URL` в `.env`. Репозиторий приватный — клонируйте, если владелец дал
доступ, либо просто распакуйте присланный ZIP-архив.

**Если что-то не так:**
- `node`/`npm` не распознаётся → закройте и откройте PowerShell заново (подхватит PATH);
- ошибка пароля БД → пароль `postgres` не совпадает, поправьте `setup.ps1` + `.env`;
- порт занят → `npm run dev -- -p 3001`;
- свежие данные из 1С → войдите `admin` → «Обзор» → синхронизация (или `SYNC_ENABLED="true"`).


## Ключевые механики

- **Закрытый доступ.** `middleware.ts` пускает только на `/login` без сессии;
  раздел `/admin/*` — лишь для роли `ADMIN`.
- **Умный поиск.** `GET /api/products/search?q=` ищет по `sku`, `fullName`,
  `name`, `brand` (регистронезависимо) и пишет запрос в `SearchLog`.
- **Фильтры каталога.** Тот же эндпоинт принимает `make`, `category`,
  `categoryGroup`, `minPrice`, `maxPrice`, `inStock`. Фасеты и дерево категорий
  отдаёт `GET /api/products/filters`. Категории в 1С плоские, поэтому дерево
  строится группировкой по первому слову («Кузов …», «Фильтр …»): выбор группы
  фильтрует по префиксу (`categoryGroup`), выбор листа — точно. Марка авто
  извлекается из применяемости при синхронизации (поля бренда в 1С нет).
- **Пагинация.** Параметр `page` (по 50 товаров на страницу); ответ содержит
  `total`, `page`, `pageSize`, `totalPages`. В каталоге — футер с навигацией по
  страницам; при смене поиска/фильтра страница сбрасывается на первую.
- **Фото товаров.** `image_url` из 1С указывает на `http://localhost:8888/...`;
  при синхронизации хост переписывается на адрес 1С, а отдаются картинки через
  прокси `GET /api/image?u=…` (обходит CORS/смешанный контент, Basic-auth,
  заблокирован на origin 1С от SSRF). Прокси **кэширует фото на диск**
  (`.image-cache/`) — раз загруженное фото показывается даже когда 1С недоступен.
  Массовая загрузка всех фото в кэш — кнопка в админ-обзоре или
  `POST /api/sync/images` (есть health-гейт: при лежащем 1С прерывается).
- **Персональные остатки.** Клиент видит `Stock` только тех складов, что
  выданы ему через `ClientWarehouseAccess`. Менеджер/админ видят все.
- **Цены — в тенге (₸).** Форматирование через `Intl.NumberFormat("ru-KZ", KZT)`.
- **Заказ → WhatsApp.** Оплата не запрашивается: заказ сохраняется в БД, цены
  пересчитываются на сервере, генерируется ссылка
  `https://wa.me/<номер_менеджера>?text=…` на закреплённого менеджера.

## Синхронизация с 1С

- Кнопка **«Синхронизировать с 1С»** в админ-обзоре (`POST /api/sync`).
- Для cron / вызова из 1С — без сессии, по заголовку:

```bash
curl -X POST http://localhost:3000/api/sync -H "X-Sync-Token: rival_sync_2026"
```

**Авто-синхронизация** работает внутри процесса Next (`instrumentation.ts` +
`node-cron`), запускается при старте сервера. Настройка в `.env`:

```env
SYNC_ENABLED="true"        # вкл / выкл
SYNC_CRON="*/30 * * * *"   # расписание (по умолч. каждые 30 минут)
```

Статус (расписание, следующий и последний запуск, результат) виден в админ-обзоре
и в `GET /api/sync/status`. Ручной и авто-запуск используют общий раннер и не
пересекаются.

Маппер устойчив к разным именам полей 1С (рус./англ., разный регистр):
проходит массив товаров, делает `upsert` `Product` по коду 1С и `upsert`
`Warehouse`/`Stock` по массиву `stocks` внутри каждого товара.
