### Окружение разработки (Windows 11)

- Новые PowerShell-сессии не видят node:
  `$env:Path = [Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [Environment]::GetEnvironmentVariable("Path","User")`
- psql: `C:\Program Files\PostgreSQL\15\bin\psql.exe` (не в PATH). **Кавычки в аргументах psql из PowerShell ломаются** — для запросов писать node-скрипт.
- **Никогда не запускать `next build` при живом `next dev`** (общий `.next`).
- Проверки: `npx tsc --noEmit` + `npx next lint`.
- **PowerShell 5.1**: нет `&&` и тернарника; here-string `@'...'@` требует `'@` в нулевой колонке — длинные коммит-сообщения писать в файл и `git commit -F`.
- `prisma migrate dev` требует остановки dev-сервера (EPERM на query_engine DLL).
- Служба PostgreSQL: `postgresql-x64-15`. **Останов/запуск требует прав администратора**, которых у ассистента нет. Один раз база слегла (бэкенды умирали на SSL-рукопожатии, в логе «процесс автоочистки запускался слишком долго» — нехватка ресурсов), помог только перезапуск службы вручную.
- Локальный `.env.local` (в git не попадает) удобно использовать, чтобы увести выгрузку заказов в тупик: `ONEC_ORDERS_URL=http://127.0.0.1:9/...` — **иначе тестовые заказы улетят в настоящую 1С заказчика**.

### Деплой на Vercel

- Build: `prisma migrate deploy && node prisma/seed.mjs && next build`.
- **Vercel блокирует деплой по автору коммита.** Рабочий обход: переименовать `.git` → `.git.deploybak`, выполнить `vercel --prod --yes`, вернуть обратно в `finally`.
- Билд валит ESLint, не только tsc — прогонять `npx next lint` перед деплоем.
- `db-seed.sql` — НИКОГДА не коммитить.

## 2. Architecture & Database

### Роли и доступ

`ADMIN` (всё) · `RA` (всё кроме «Настроек») · `MANAGER` · `ACCOUNTANT` (read-only) · `CLIENT`.
Матрица — `lib/permissions.ts` (`SECTION_ROLES`), гейт — `middleware.ts`. Скоупинг менеджера — `lib/admin-scope.ts`: MANAGER видит **только своих клиентов** и всё, что они породили.

### Модели (`prisma/schema.prisma`, 15 миграций, последняя `20260731074839_user_telegram_id`)

- **User**: role, login (уник.), passwordHash, fullName, email (уник.), phone, **telegramId**, address, city, balance (долг < 0), discountPercent *(legacy, см. §3)*, isActive, debtSince, managerId (self-relation ManagerClients).
- **Product**: code (уник., ключ upsert из 1С), sku, name, fullName (применяемость), brand/model, category, price, oldPrice + priceDropAt, **isFinalPrice**, newUntil, pinned, badge (NEW|HIT), skuNorm/fullNameNorm, GIN trigram индексы.
- **Warehouse**, **Stock** (productId+warehouseId, qty), **ClientWarehouseAccess**.
- **Order**: status, comment, **paymentMethod** (CASH|TRANSFER), **deliveryMethod** (DELIVERY|PICKUP), total, paid, debtApplied, onecSent, onecNumber. **OrderItem**: снимки sku/name/price/qty + isGift.
- **Return** (в 1С не уходит), **Favorite**, **SavedCartItem**, **ProductView**, **SearchLog**, **Analog** (code→sku), **Setting**, **Broadcast**/**BroadcastProduct**/**BroadcastRecipient**.
- **DiscountRule**: kind DISCOUNT|MARKUP, percent 1..95, userId (null = всем), target ALL|PRODUCT|CATEGORY|BRAND.
- **GiftRule** + **GiftRuleTrigger**/**GiftRuleGift**.

**Каскады при удалении Product** (важно для синка): `OrderItem`/`Return` → **SetNull** (заказы уцелеют, в них свой снимок sku/name/price); `Stock`, `Favorite`, `SavedCartItem`, `ProductView`, `BroadcastProduct`, `DiscountRuleProduct`, `GiftRuleTrigger`, `GiftRuleGift` → **Cascade**.

### Интеграция с 1С (`lib/onec.ts`)

- Фид: `ONEC_API_URL` (Basic-auth), ~5400 товаров, синк ≈8–10 с.
- **Семантика синка (три правила, добытые разбором боевых багов):**
  1. **Первый импорт в пустой каталог НЕ ставит значок «Новинка».** Иначе новыми оказываются все товары сразу и вся витрина в значках — именно так и вышло при запуске.
  2. **Остатки, пропавшие из выгрузки, удаляются.** 1С перестаёт слать склад, когда товар там кончился; раньше строка висела вечно и повторный синк её не чинил (склада нет во входных данных). Поле `stocksRemoved`.
  3. **Товары, пропавшие из выгрузки, удаляются** — поле `productsRemoved`. **С защитой:** если выгрузка меньше 50 % текущего каталога, удаление пропускается, причина в `removalSkipped` (синк идёт автоматически, обрезанный ответ 1С иначе снёс бы каталог).
- Заказы → 1С: `lib/onec-orders.ts`, POST `…/hs/v1/orders`.
- Планировщик: `instrumentation.ts` → `lib/scheduler.ts` (cron из Setting `sync_cron`) + maintenance каждые 10 мин (`lib/maintenance.ts`).
- Скрытые категории: `Unused`, `Архив папки` (`lib/categories.ts`).
- Фото: прокси `GET /api/image?u=` (SSRF-lock), диск-кэш `.image-cache/`.
- Кэш: `lib/cache.ts` in-process TTL. Пользовательские ключи **обязательно** с `session.sub` (`wh:`, `disc:`), общие — `cfg:`, `catalog:`, `gifts:`.

### Дерево категорий (`lib/category-tree.ts`)

В 1С категории **плоские** (51 строка). Заказчик потребовал 3-уровневое дерево, где зонтики «Тормозные колодки», «Фильтра», «Ремкомплект» **в 1С не существуют**. Поэтому структура задана явной картой в коде. Фильтр по группе разворачивается в точный список категорий (`categoriesUnderPath`), а не в поиск по префиксу. Категории, которых нет в карте, автоматически падают в конец корня — новые папки из 1С не теряются.

## 3. Knowledge Base — ключевые бизнес-правила

### Скидки и наценки (`lib/pricing.ts` — единственный источник истины)

- **Расчёт:** берётся ЛУЧШАЯ скидка (max из `global_discount`, `User.discountPercent`, правил kind=DISCOUNT по ALL/CATEGORY/BRAND/PRODUCT) и ЛУЧШАЯ наценка (max правил kind=MARKUP). **net = скидка − наценка**, cap ±95.
- **`isFinalPrice` блокирует ТОЛЬКО скидку. Наценка применяется ко ВСЕМ товарам, включая `isFinalPrice=true`** — критичное требование, проверено.
- **Клиент НЕ видит личную скидку.** В бейдж и зачёркивание идёт ТОЛЬКО акция 1С (из `oldPrice`, живёт `price_drop_days`). Нет снижения от 1С → нет бейджа вообще, даже при личной скидке. Наценка тоже невидима — просто выше цена.
- Бейдж показывается, **только если итоговая цена реально ниже старой** — иначе наценка поверх акции 1С рисовала зачёркнутую цену НИЖЕ текущей.
- Заказ пере-ценивается на сервере (`/api/orders`), клиентским ценам не доверяем.
- **Скидки живут в одном месте — разделе «Скидки».** Поле «Личная скидка» из карточки клиента убрано (менеджеры не понимали, каким из двух путей назначать). Колонка `User.discountPercent` всё ещё учитывается в ценообразовании ради обратной совместимости → перенести остатки скриптом `migrate-personal-discounts.mjs`.

### «Диски UIDNU» — строго парами (`lib/pair-only.ts`)

- Категория определяется точным сравнением `category` с «диски uidnu».
- В БД цена за 1 шт, но **карточка показывает цену ×2 с подписью «цена за 2шт»** (подпись динамическая: выбрал 4 → «цена за 4шт»).
- Количество строго чётное ≥ 2. `snapPairQty` продублирован на трёх уровнях: стор корзины, `/api/cart`, `/api/orders`.

### Подарки (`lib/gifts.ts` + `lib/gift-earn.ts`)

- Купи ≥ `minQty` любого товара-триггера → товары-подарки бесплатно. **Кратность: каждые полные minQty дают ещё комплект** (floor(qty/minQty)), правила стакаются.
- Сервер добавляет подарки строками `price=0, isGift=true`; уходят и в 1С, и в WhatsApp/почту/Telegram с пометкой.
- UI: зелёный баннер на триггерах, зелёные строки в корзине, пилюля «+N» в мини-корзине.
- **Тексты возврата в корзине:** есть заработанный подарок → янтарный блок с `return_policy_gift`, иначе серый с `return_policy_default`. Оба правятся в Настройках.

### Оформление заказа

- Клиент выбирает **способ оплаты** (Наличный расчёт / Перевод) и **способ доставки** (Доставка / Самовывоз).
- Адрес берётся **только из карточки клиента** (населённый пункт + адрес), в корзине не редактируется.
- **Комментарий для 1С** (`buildOneCComment`) — **БЕЗ префикса «Заказ с сайта №…»**: 1С подставляет его сама из `site_order_id`, и наш дубль давал «Заказ с сайта №X. Заказ с сайта №X. Доставка…».
  - самовывоз → `Самовывоз`
  - доставка → `Доставка, Адрес: Казахстан, Алматы, Жибек жолы 11 (комментарий)`
- Заказ доступен **только роли CLIENT** и только активному аккаунту (`isActive`) — BlockOverlay был лишь UI.
- Количество капится 100 000 на всех уровнях; WhatsApp-текст обрезается до 40 позиций (иначе ломается URL).

### Уведомления о заказе

- **Почта** (`lib/mail.ts`, nodemailer, Gmail SMTP): уходит на e-mail закреплённого менеджера, запасной — `ORDER_MAIL_TO`. Шаблон повторяет присланный заказчиком образец: «Информация о клиенте» (Клиент, Контактное лицо, Телефоны, Email, Способ оплаты, Способ доставки, Адрес доставки) и таблица `Наименование детали | Заказано | Срок | Направление | Кол-во | Сумма`. «Срок» = «в наличии»/«под заказ» по остаткам, «Направление» = склады с остатком (считаются на момент письма).
- **Telegram** (`lib/telegram.ts`): бот шлёт менеджеру ФИО, телефон, почту, оплату, доставку, адрес, комментарий, состав и сумму. Нужен `TELEGRAM_BOT_TOKEN` (**полный, с двоеточием — номер бота не подойдёт**) и заполненный `telegramId` у менеджера. **Менеджер обязан сам нажать «Start» у бота** — Telegram запрещает боту писать первым.
- Обе отправки best-effort и **логируют причину сбоя** (`[mail]` / `[telegram]`), иначе «не работает» неотличимо от «не настроено».

### Поиск

- Умный матч по sku/name/fullName + нормализованным полям + аналогам. Марка не матчится текстом (фасет), **фильтр по модели = текстовый поиск слова в full_name**.
- **Exact match:** запрос == sku/code/fullName → такие товары принудительно первыми, выделение **только рамкой**, без иконок и бейджей.
- **Автоочистка:** `components/SearchReset.tsx` чистит строку при смене маршрута, КРОМЕ переходов с `?q=`.
- **История поиска** (`lib/search-history.ts`, localStorage, до 8): фокус в пустую строку → выпадашка с иконкой часов и удалением по крестику.

### Прочее

- **Остатки для клиента капятся: > 70 показывается как «>70»** (`lib/stock.ts`), персонал видит точные.
- Заблокированный клиент логинится и видит BlockOverlay, но **заказ оформить не может** (гейт на сервере).
- Менеджер **не может передать своего клиента** другому или снять закрепление — теряется доступ безвозвратно. Только ADMIN/RA. Новый клиент, созданный менеджером, автоматически закрепляется за ним.

## 4. Current State — реализованный UI/UX

### Каталог

- Вид по умолчанию — **сетка**; при непустом поисковом запросе автоматически переключается на **список** (лучше читается при поиске по артикулу), при очистке — обратно.
- **Локальный выбор количества на карточке:** ± меняет количество и **цена (и зачёркнутая) пересчитывается на глазах**, в корзину уходит только по кнопке. Зелёная вспышка «Добавлено», подсказка «В корзине: N шт». Работает **и в сетке, и в списке**.
- **Мобильный каталог:** сетка в 2 колонки (4 карточки в поле зрения), уменьшенные текст/отступы, кнопка корзины **только иконка**. Список: строки фиксированной высоты 92px (не зависят от длины применяемости и числа складов), скрыта колонка «Категория», ширина 768px вместо 1040.
- **Подсказка с полным текстом применяемости** (`ClampedText`) — по наведению И по нажатию (на телефоне hover не существует), появляется только если текст реально обрезан, позиционируется `fixed` (в таблице absolute обрезало бы).
- Пагинация **сверху и снизу** — на телефоне до нижней надо было листать 50 карточек.
- Внутренний код 1С скрыт от роли CLIENT.
- Заглушка `/no-photo.png` для товаров без фото.
- Дерево категорий на 3 уровня со счётчиками.

### Корзина и заказ

- Способ оплаты и доставки, подтверждение оформления в модалке (`ConfirmDialog`), надпись про WhatsApp убрана.
- **Репрайс при открытии** (`/api/cart/reprice`): цены в localStorage устаревают, если админ поменял скидки, — «Итого» теперь всегда совпадает с тем, что спишет сервер.
- Десктопная таблица использует общий `CartQtySelector` (очищаемый ввод).

### Админка

- **Заказы:** строка раскрывается — состав заказа, фото по наведению, клик уводит в каталог по артикулу. Права: менеджер видит только своих (403 на чужой заказ).

- **Аналоги:** файл разбирается **в браузере** и грузится порциями по 10 000 (≈566 КБ на запрос) с прогрессом — цельная загрузка 7.22 МБ не пролезала (Vercel режет тело на 4.5 МБ, у IIS свои лимиты).

### Общее

- Сворачиваемый **Mini Sidebar** на десктопе (w-60 → w-20, состояние в localStorage), кнопка на границе — тёмный квадрат в палитре меню.
- **«Возвраты» — вкладка внутри «Моих заказов»** (`?tab=returns`), `/returns` → redirect.
- Мобильное меню: `h-[100dvh]` вместо `h-screen` — на iOS Safari кнопка «Выйти» уезжала под панель браузера.

- Демо-версии нет: плашка с демо-доступами убрана, сид создаёт **только** admin и не перезаписывает существующий пароль.

## 5. Эксплуатационные скрипты (`scripts/`)

Все — **режим проверки по умолчанию**, применение флагом `--yes`. Пароли и токены только через переменные окружения, в git не попадают.

| Скрипт | Назначение |
|---|---|

| `import-users.mjs --managers --clients <xlsx>` | импорт 6 менеджеров и клиентской базы; **отказывается перезаписывать сотрудника клиентом**, конфликты почты обходит |
